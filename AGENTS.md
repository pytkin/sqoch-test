# Sqoch

- Функциональный объём — [бриф](docs/brief.md), стек и API —
  [техническая спецификация](docs/technical-specification.md), процесс и матрица
  проверок — [план работ](docs/work-plan.md), результаты — [приёмка](docs/acceptance.md).
- Перед изменением интерфейса прочитай [дизайн-систему](docs/design-system.md).
  Применяй [навык качества дизайна Sqoch](docs/skills/sqoch-design-quality/SKILL.md).
  Прежняя визуальная система отклонена пользователем 27 октября 2026 года;
  сохраняется логотип, выбран третий вариант последнего минерального набора.
  Трекинг немного
  увеличен; длинное тире U+2014/U+2015 в авторском UI-тексте не используется.
  Типографика, переносы, иконки, кнопки и depth проверяются как единая система.
  UI-тексты следуют [редакционным правилам](docs/design-system.md#редакционные-правила).
- Первый этап — `src/features/booking`, без сохранения покупок. Второй —
  отдельный `src/features/organizer` и ограниченное расширение `backend/`:
  [требования](docs/notifications.md), [технические решения](docs/notifications-technical.md).
  Разрешены SQLite/sqlite3, DeepSeek и SMTP только в локальный Mailpit.
  Без ORM, внешней доставки, оплаты, авторизации и публичного deployment.
- Для поведения сначала положительные/отрицательные тесты и содержательный
  red, затем минимальная реализация и green. Ошибки установки и импорта —
  неполадка каркаса, а не red приложения. Указывай фактические проверки и
  предел доказательства; завершённые изменения остаются зелёными. Для второго
  этапа время не учитывается, отдельный отчёт о незавершённом не требуется;
  статусы срезов и критерии готовности сохраняются.
- Pydantic владеет контрактом. При изменении API обнови генерацию типов и
  потребителя; проверь `contracts:check`. TS6 допустим только в `tools/openapi`.
- Прямые версии закреплены, установка frozen/locked. Node/pnpm из окружения
  и `uv --python` допускают override; не понижай стек без согласования.
- Запуск и команды находятся в [README](README.md); `agent-platform.json`
  объявляет шесть стандартных операций обычными командами pnpm. Приватных
  инструментов, SSH-ключей и RTK для работы с проектом не требуется.
- Сохраняй чужие изменения. Перед коммитом проверь состав diff и подходящие
  проверки. Не заявляй непроверенную готовность или внешний результат.
  Push, публикация и отправка материалов требуют отдельного разрешения.
- Второй этап реализуется по срезам с TDD и новым независимым ревью после
  каждого среза; подтверждённые P0–P2 закрываются до перехода дальше.
  Текущий статус и свидетельства принадлежат плану/приёмке. Итоговое видео — только
  после готовности и отдельного указания пользователя; процесс не записывать.
