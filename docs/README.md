# Документация Sqoch

Обе волны находятся в одном приложении: оформление билетов без сохранения
покупок и отдельный кабинет организатора с SQLite, DeepSeek и локальным
Mailpit. Рабочие команды и настройка окружения находятся в
[корневом README](../README.md).

## Требования и решения

У каждого вида требований один владелец. При изменении поведения
обновляется соответствующий документ; отчёт прошлой проверки не меняет
согласованный объём.

| Документ                                                      | Чем владеет                                                                                 |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| [Бриф](brief.md)                                              | Правила оформления REQ-01–11, источники и решения первого этапа                             |
| [Уведомления](notifications.md)                               | Границы второго этапа, требования N-01–16 и пользовательский путь                           |
| [Техническая спецификация](technical-specification.md)        | Общий стек, владение модулями, booking API и генерация типов                                |
| [Технические решения уведомлений](notifications-technical.md) | SQLite, подтверждение, AI, worker, SMTP и восстановление                                    |
| [Точный контракт уведомлений](notifications-contract.md)      | DTO, ошибки API и связь проверок T01–T30 с текущими файлами                                 |
| [Дизайн-система](design-system.md)                            | Выбранный третий минеральный kit, типографика, компоненты и редакционные правила обеих волн |
| [Инварианты интерфейса](design/interaction-invariants.md)     | Поведение и доступность, сохраняемые при изменении визуальной системы                       |
| [План работ](work-plan.md)                                    | Срезы, процесс TDD, review-gates и матрицы покрытия                                         |

Pydantic остаётся владельцем исполняемой схемы API; TypeScript-типы
генерируются в `src/api/generated`. Проектные инструкции находятся в
[AGENTS.md](../AGENTS.md), применение визуальных правил описывает
[навык качества дизайна](skills/sqoch-design-quality/SKILL.md).

## Реализация и результаты

- [Приёмка](acceptance.md): фактические прогоны, ограничения доказательств
  и результаты срезов. Числа тестов относятся к указанному прогону.
- [Cleanup проекта](reports/project-cleanup-20261027.md): организация материалов,
  проверка сохранности требований и запуска по README.
- [Браузерная приёмка от 27.10.2026](reports/event-transfer-browser-20261027.md):
  последний завершённый поведенческий прогон, **897 passed**
  (346 frontend, 432 backend, 45 tooling, 74 desktop/mobile E2E),
  42/42 предметные мутации и readback восьми писем локального Mailpit.
- [Видеодемонстрации](demo/README.md): текущий путь организатора и сохранённое
  историческое оформление билетов. Новое видео записано по отдельному
  указанию пользователя после браузерной приёмки.
- [Мероприятия и подготовка переноса](event-transfer-implementation.md):
  завершённые SQOCH-39–44, TDD-критерии, переход данных и gates.
  Журнал сохраняет результаты этих срезов; последующая браузерная приёмка
  приведена отдельно выше.
- [Рефакторинг обеих волн](history/refactoring-20261027.md): завершённые SQOCH-34–37,
  сохранение поведения на том срезе и проверка качества тестов.
- [Живые DeepSeek/SMTP после рефакторинга](acceptance.md#sqoch-38-живые-интеграции-после-рефакторинга):
  SQOCH-38, отдельные тестовые данные, фактический readback и границы результата.
- [Design QA](history/design/design-qa-sqoch-33-20261027.md): сопоставление реализованных экранов с выбранным
  kit, screenshots и пределы визуальной приёмки SQOCH-33.
- [Backend TDD](../backend/TDD.md): история содержательных red/green циклов;
  актуальная команда backend suite приведена в README.

Текущий статус определяется планом и приёмкой. Сохранённый PASS подтверждает
тот срез и ту среду, которые названы в отчёте; последующие изменения требуют
подходящих проверок.
