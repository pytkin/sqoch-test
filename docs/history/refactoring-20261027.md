## Стратегия регрессии и мутаций

До переносов добавляются характеристические и отрицательные тесты фактических
границ. Их прохождение на прежнем коде является защитой рефакторинга, а не
сфабрикованным TDD red. Для подтверждённого дефекта даты сначала фиксируется
HTTP 500/ожидаемый 422, затем минимальное исправление и green.

Мутации выбираются по риску: возраст/цена, точный deadline, отмена/поздний
ответ, корректность DTO, состояние/счётчики, retry и optimistic/CAS guards.
Изменяются изолированные копии. Исходный green обязателен; ошибки импорта,
синтаксиса, сборки или harness не выдаются за обнаруженную бизнес-ошибку.
Конечный набор смысловых мутаций не является исчерпывающим AST-покрытием
и не даёт глобальный mutation score всему проекту.

Итоговые изменения, команды, результаты независимых ревью и границы
доказательства собраны ниже. Исторические документы
остаются историческими; актуальные результаты учитываются отдельно.

## Выполненный рефакторинг

Frontend: `Organizer.tsx` 1146 → 854 строки, `organizer/api.ts` 375 → 185,
`booking/api.ts` 193 → 176. Готовые UI-поверхности и feature-local примитивы
отделены от оркестрации. Поллинг, UUID, readback и focus intents сохранили
владельца. Чистые `form.ts`/`responseGuards.ts` проверяются отдельно.
Повторявшийся deadline/cancellation выделен в `src/api/abortable.ts` (29 строк),
а разные HTTP/error semantics остаются у feature API.

58 прежних booking cases перенесены из большого App.test в четыре
feature suites с отдельным fixture на каждый тест. Независимая AST-сверка
подтвердила сохранность всех 48 исходных test calls и assertions; отличие
числа calls от cases объясняется параметризацией. Дополнены прямые границы
возраста/склонений/дат, DTO, отмены, очистки ресурсов и точного deadline.
Frontend: 123 → 222 green tests.

Backend: `campaign_queries.py` строит DTO в переданном соединении;
`errors.py` владеет ошибками и общей optimistic проверкой;
`deepseek.py` владеет протоколом/HTTP/deadline/cleanup провайдера.
Use cases сохраняют владение транзакциями и разрешёнными AI tools.
AST-сверка 53 SQL/BEGIN вызовов не нашла добавленных/удалённых SQL-выражений.
OpenAPI базы и результата совпадают, генерация типов синхронна.

Подтверждённый дефект: три непредставимые крайние даты сначала дали HTTP
500 вместо ожидаемого 422. Узкое исправление ручного валидатора переводит
OverflowError/ValueError в штатную validation error; три HTTP теста green
и дополнительно проверяют неизменность черновика/мероприятий. Добавлены
проверки unsettled состояний, event isolation, старого CAS результата,
позднего prepare и tool/HTTP budgets. Backend: 291 → 316 green tests.

Документация: владельцы и команды согласованы с кодом, текущие план/приёмка
отделены от двух подробных historical ledgers с поправкой относительных
ссылок. Независимая обратная нормализация восстановила baseline побайтово;
сохранены 44 исходные link targets. Все REQ-01–11 и N-01–16 неизменны.
В `backend/TDD.md` уточнены исторический scope/число тестов и текущая команда;
его исходный byte hash в snapshot отсутствовал, поэтому полная побайтовая
дельта этого одного ledger не заявляется.

## Результат смысловых мутаций

[Машиночитаемый отчёт](../quality/refactoring-mutations-20261027.json) содержит
33 IDs, намерение, группы проверок, before/after paths и SHA исходного и
изменённого текста. Регистр и повторяемая команда находятся в
`../scripts/mutation-cases.mjs` и `pnpm test:mutation`.

| Набор                         | Обнаружены тестами | Пропущены тестами | Invalid | Timeout |
| ----------------------------- | ------------------ | ----------------- | ------- | ------- |
| Исходный код и исходные тесты | 11                 | 22                | 0       | 0       |
| Рефакторинг и усиленные тесты | 33                 | 0                 | 0       | 0       |

В обоих полных прогонах сначала прошли все шесть неизменённых controls.
Примеры закрытых пробелов: unsafe integer age, 11–14 в склонении,
неверный успешный HTTP status, слишком ранний deadline, дубли recipients,
несогласованные state counters, несуществующая календарная дата, старый
SMTP результат, отдельные unsettled состояния и event isolation, повтор
ID tool call и допустимая граница HTTP budget.

Сравнение включает структурные изменения кода и новые тесты. Это конечный
набор предметных мутаций, не общий процент тестового покрытия и не
исчерпывающий AST score. Промежуточный отсутствующий before anchor для
перенесённого final-tools guard исправлен соответствующим старым выражением;
полные конечные наборы повторены без invalid.

Повторить текущий набор после `pnpm setup`:

```sh
pnpm test:mutation
```

Полный отчёт и логи пишутся в `.cache/mutation/current/`. Исходники меняются
только в копиях без .env, локальных SQLite/venv/cache. Симлинки в исходной
closure отклоняются. `node_modules` подключается отдельно для неизменённых
установленных зависимостей. Code 0 означает все выбранные мутации killed;
1 означает survived; 2 означает invalid/timeout либо failure control.
При control failure текущий JSON имеет новый runId/status blocked и причину;
прошлый успешный результат не остаётся результатом неудачного запуска.

Независимое ревью runner нашло три P2: parse failure считался killed,
симлинк нарушал изоляцию, при control failure оставался stale report.
Три новые отрицательные проверки дали red до фиксов и green после.
Рецензент повторил настоящие parse/symlink/stale-report probes и подтвердил
закрытие. Дополнительно docs checker теперь проверяет root Markdown,
включая docs/history/design/design-qa-sqoch-33-20261027.md: missing capture дал red, затем green.
